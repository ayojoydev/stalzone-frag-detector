# SZFD · Stalzone Frag Detector

**Меньше поиска по записи. Больше готовых моментов.**

Локальный поиск фраг-плашек, таймкоды и нарезка целых серий убийств.
Цветное консольное меню, headless-инструмент для монтажных агентов и Python API —
одно общее ядро.

## Что умеет

- **Находит фраги** по белому значку черепа в нижней центральной части кадра.
- **Сохраняет серии целиком:** продление иконки новым убийством не обрезает момент.
- **Подстраивается под размер и пропорции кадра:** 4:3, 5:4, 16:9, 16:10, ultrawide и 4K.
- **Работает без знания команд:** в цветном меню достаточно цифр и стрелок.
- **Помогает проверить результат:** CSV с таймкодами и кадры с выделенным значком.
- **Возвращается к моменту перед смертью игрока**, чтобы найти быстро исчезнувшую плашку.
- **Встраивается в другие приложения** через типизированный Python API.
- **Работает как инструмент монтажного агента:** принимает видео и параметры без окон,
  возвращает CSV и готовые клипы с предсказуемыми именами.

Обработка выполняется на вашем компьютере. Исходная запись не изменяется.

## Быстрый старт

### Просто пользоваться — Windows

1. Откройте [Releases](https://github.com/ayojoydev/stalzone-frag-detector/releases).
2. Если в выбранной версии есть **`SZFD-Setup.exe`**, запустите мастер установки.
   Для переносного варианта достаточно **`SZFD.exe`** — установки не требуется.
3. Откройте SZFD, нажмите **1** и выберите видео.
4. При необходимости включите **6 → 1 «Мультикиллы»**, затем нажмите **7**.
5. После обработки нажмите **8**, чтобы открыть результаты.

Python и PowerShell для EXE не нужны. Установщик работает для текущего пользователя
без прав администратора и создаёт ярлыки приложения.

> **Доступность сборок зависит от релиза.** Здесь описаны возможности текущего
> исходного кода. Новые варианты EXE, установщик и библиотечный пакет появятся
> в Releases только после их публикации владельцем репозитория.
> Если нужного файла нет, используйте запуск из исходников ниже.

### Запустить из исходников

Нужны **Python 3.10+**, компонент **Tcl/Tk** для выбора файлов и интернет для
первой установки зависимостей.

1. Скачайте или клонируйте проект.
2. Откройте **`run_detector.bat`** двойным щелчком.
3. Если окружение ещё не подготовлено, автоматически запустится **`setup.bat`**.

Видео также можно перетащить на `run_detector.bat`: меню откроется с выбранной записью.
FFmpeg для нарезки поставляется зависимостью `imageio-ffmpeg`; обычно устанавливать
его отдельно не нужно.

## Три способа использования

### 1. Цветное консольное меню — `SZFD.exe`

Для тех, кто хочет выбрать файл и начать обработку без ручного ввода флагов.

- **1** — выбрать видео или проверочный скриншот.
- **2** — выбрать папку результатов.
- **3** — включить или отключить нарезку.
- **4** — сохранять проверочные кадры.
- **5** — переключить быстрый и точный режимы нарезки.
- **6** — открыть настройки, включая режим мультикиллов.
- **7** — начать обработку.
- **8** — открыть результаты.
- **9** — выйти.

**↑ ↓ ← →** перемещают выбор, **Enter** активирует пункт, **Esc** возвращает назад.
Цифра выбирает пункт сразу, без дополнительного Enter. Во время обработки
**Ctrl+C** останавливает её и возвращает в меню.

Настройки выбираются из готовых вариантов, а файлы — через обычный системный диалог.
Нарезка включена по умолчанию. После установки Python-пакета меню доступно как `szfd-menu`.

### 2. Инструмент для нейросетевого монтажа — `SZFD-CLI.exe`

Headless-версия без меню, диалогов и обязательного участия человека. Монтажный
агент или другая система запускает один процесс на видео, проверяет код возврата,
читает CSV с границами моментов и забирает готовые клипы. Исходное видео не меняется.

Рекомендуемый профиль для автоматической нарезки:

```powershell
.\SZFD-CLI.exe `
  --input "D:\Video\match.mp4" `
  --output "D:\Video\montage" `
  --frame-step 30 `
  --multikill `
  --cut-before 10 `
  --cut-after 10 `
  --multifrag-gap 10 `
  --quiet
```

Для записи 60 FPS используйте `--frame-step 30`, для 120 FPS — `--frame-step 60`.
В общем случае агент может брать шаг `round(FPS / 2)`: это одна проверка примерно
каждые полсекунды. Для только таймкодов достаточно убрать `--multikill`.

После успешного запуска агент получает:

```text
D:\Video\montage\match_frags\
├── match_fragtime.csv
└── clips\
    ├── moment_001_00-03-58.mp4
    └── ...
```

Код возврата `0` означает успешную обработку видео, `1` — ошибку. Отсутствие
моментов не считается ошибкой: в этом случае CSV существует и содержит только
заголовок. Интеграции должны опираться на код возврата и файлы, а не разбирать
текст прогресс-бара или стандартный вывод.

Полный сценарий для LLM-агентов, пакетной обработки и монтажных пайплайнов:
**[AGENT_INTEGRATION.md](AGENT_INTEGRATION.md)**.

Дополнительные примеры:

```powershell
# Только таймкоды
.\SZFD-CLI.exe --input "D:\Video\match.mp4" --quiet

# Точные границы ценой перекодирования
.\SZFD-CLI.exe --input "D:\Video\match.mp4" --multikill --cut-mode exact --quiet

# Справка
.\SZFD-CLI.exe --help
```

После установки Python-пакета вместо `.\SZFD-CLI.exe` используйте `szfd-cli`.
Совместимые команды `SZFD` и `szfd` также сохранены: без аргументов — меню,
с `--input` — обычная обработка. Меню можно явно включить флагом `--menu`.

### 3. Библиотека — `import szfd`

Анализ в памяти и отдельный экспорт результатов. Без окон, разбора аргументов
командной строки и вызовов `sys.exit()`. [Пример ниже ↓](#python-api)

## Мультикиллы

Один килл показывает значок примерно на 5 секунд. При продолжении серии значок
может оставаться видимым, поэтому ориентироваться только на его первое появление
недостаточно: часть момента попадёт за конец короткого клипа.

**`--multikill` сохраняет весь период показа иконки**, а не только несколько секунд
вокруг первого совпадения. Флаг автоматически включает нарезку.

```text
                     непрерывный показ иконки
                     ├──────── 10 с ────────┤
       5 с до        │                      │      3 с после
    ├────────────────┴──────────────────────┴──────────────┤
    └──────────────── один клип: 18 с ─────────────────────┘
```

```powershell
.\SZFD-CLI.exe --input "match.mp4" --multikill --multifrag-gap 10 --cut-before 5 --cut-after 3 --cut-mode exact
```

**Правила объединения:**

- Интервал между соседними продолжениями серии — не больше **10 секунд**
  (`--multifrag-gap`). Вся цепочка при этом может быть значительно длиннее.
- Для непрерывно видимой иконки последнее убийство **оценивается** как конец
  показа минус время иконки одиночного килла (`--plaque-duration`, по умолчанию 5 секунд).
- Конец показа оценивается по последнему совпадению плюс один интервал проверки
  кадров. Для меньшей погрешности используйте `--frame-step 5` или `1`.
- Клип начинается за `--cut-before` до первого появления и заканчивается через
  `--cut-after` после оценённого конца показа последней плашки. Границы не выходят за видео.

Режим сохраняет также одиночные моменты, а не только серии. Файлы называются
`moment_...`: количество убийств не подставляется, поскольку оно не известно точно.
Без `--multikill` сохраняется прежняя логика коротких клипов вокруг начала событий.
Псевдоним флага — `--multikills`.

> Нижний череп — **индикатор вашего убийства**, а не вашей смерти.
> Отдельное распознавание экрана смерти используется для повторной проверки кадров
> перед гибелью игрока. По одной непрерывной иконке нельзя достоверно посчитать убийства.

## Результаты и качество нарезки

Без нарезки CSV сохраняется рядом с видео или в `--output`. С `--cut` либо
`--multikill` результаты собираются в отдельную папку:

```text
match_frags/
├── match_fragtime.csv       таймкоды и границы моментов
├── clips/                  клипы, если включена нарезка
└── debug/                  проверочные кадры, если включён --debug
```

**Быстрый режим `--cut-mode copy`** используется по умолчанию: без пережатия,
но начало клипа может сместиться к ключевому кадру.
**Точный режим `--cut-mode exact`** перекодирует видео и соблюдает рассчитанные
границы. Он медленнее и не устраняет погрешность самого распознавания.

В CSV `hits` — число срабатываний, включая подтверждения повторного прохода
перед смертью (как в версии 0.5), а не число уникальных кадров. `group_size` — количество
эпизодов показа в моменте, **не точное число убийств**. `clip_start` и `clip_end`
содержат границы клипа; `visible_seconds` — наблюдаемую длину эпизода.

## Настройка распознавания

Разрешение выбирается автоматически. Шаблон проверяется как с масштабированием
HUD по высоте, так и с растяжением по осям, включая 4:3 ↔ 16:9.
Стандартная область поиска адаптируется к пропорциям; вручную заданная `--roi`
остаётся точной.

По умолчанию проверяется каждый 30-й кадр, событие подтверждается двумя
совпадениями. При коротких плашках или низком FPS уменьшите шаг:

```powershell
.\SZFD-CLI.exe --input "match.mp4" --frame-step 5 --min-hits 1 --debug
```

`--merge-gap` объединяет **кадры одной плашки**, а `--multifrag-gap` — убийства
в одну серию. Это разные настройки. Интервал объединения кадров автоматически
ограничивается снизу фактическим шагом проверки (`frame-step / FPS`), иначе
обычная плашка могла бы распасться на одиночные совпадения и исчезнуть из результата.
Например, при проверке раз в секунду `--merge-gap 0.5` будет повышен примерно до 1 секунды;
CLI сообщит об этом. Для меньшего интервала сначала уменьшите `--frame-step`.

Если есть ложные срабатывания, попробуйте `--threshold 0.78` или `0.82`.
ROI задаётся долями размера кадра: `x1,y1,x2,y2`. Стандартная область фрага —
`0.36,0.68,0.64,0.86`. Настройки можно проверить на одном скриншоте:

```powershell
.\SZFD-CLI.exe --input "frame.png" --debug
```

Для изображения код возврата **0** означает, что плашка найдена, **2** — не найдена.
Для видео **0** означает успешную обработку, даже если событий нет; ошибка — **1**.

## Python API

Для библиотеки нужен Python 3.10+. Установка из каталога проекта:

```powershell
python -m pip install .
```

Также можно установить `.whl` из соответствующего релиза.

```python
from szfd import DetectorOptions, analyze, export

options = DetectorOptions(
    multikill=True,
    multifrag_gap=10,
    cut_before=5,
    cut_after=3,
    cut_mode="exact",
)

# Только анализ: не создаёт CSV и клипы.
analysis = analyze("match.mp4", options)
for moment in analysis.clip_groups:
    print(moment.start_seconds, moment.end_seconds)

# Сохранение — отдельное явное действие.
saved = export(analysis, output="results")
print(saved.csv_path)
print(saved.clips)
```

Для анализа и сохранения за один вызов:

```python
from szfd import DetectorOptions, process

saved = process("match.mp4", output="results", options=DetectorOptions(multikill=True))
```

- **`DetectorOptions`** — неизменяемые настройки.
- **`AnalysisResult`** — детекции, эпизоды, группы клипов, FPS и длительность.
- **`ExportResult`** — анализ и пути к CSV, каталогу результатов и клипам.
- **`PlaqueDetector.detect(frame)`** — обработка отдельного BGR-кадра NumPy.

Библиотека по умолчанию не печатает прогресс; `quiet=False` включает его.
Ошибки передаются обычными исключениями Python.
Ещё один пример: [`examples/library_usage.py`](examples/library_usage.py).

## Разработка и сборка

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --editable ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют группировку серий, разные разрешения, CLI, меню и библиотечный API.
Интеграционная проверка создаёт видео и действительно нарезает его через FFmpeg.
Локальный запуск тестов интерфейса требует Tcl/Tk и графического сеанса.

```text
szfd/
├── core.py                 общее ядро: поиск, события, CSV и нарезка
├── api.py                  публичный библиотечный API
├── cli.py                  команды и разбор флагов
├── terminal.py             цветное консольное меню
└── assets/                 шаблоны распознавания
```

## Ограничения

- Это распознавание изображения, а не чтение игровых событий или ников.
- Несколько убийств без исчезновения значка выглядят как один эпизод. Режим
  мультикиллов сохраняет его целиком, но не гарантирует точного подсчёта убийств.
- Интервал для непрерывной иконки оценивается по времени её показа. Смерть игрока,
  пропуски распознавания и особенности таймера могут влиять на оценку.
- Чёрные поля, обрезка, сильное сжатие, изменённый HUD и слишком маленький значок
  могут потребовать другой ROI, порога или собственного шаблона.
- Поддержка размера кадра не означает гарантированного распознавания любого HUD.
