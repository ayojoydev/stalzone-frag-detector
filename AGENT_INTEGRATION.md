# SZFD для монтажных агентов

Этот документ задаёт рабочий контракт для LLM-агента, оркестратора или
автоматизированного монтажного пайплайна. Для интеграции используйте
`SZFD-CLI.exe` либо команду `szfd-cli`: они не открывают меню и не требуют кликов.

## Задача инструмента

SZFD находит в записи Stalzone плашки убийств, объединяет близкие события в один
момент, записывает границы в CSV и при необходимости сразу создаёт клипы через
FFmpeg. Инструмент не меняет исходное видео и не принимает монтажных решений за
пределами найденных фраг-моментов.

## Алгоритм агента

1. Убедиться, что входной файл существует и является видео.
2. Определить FPS из метаданных видео.
3. Выбрать `frame-step = max(1, round(FPS / 2))`.
   Для 60 FPS это 30, для 120 FPS — 60.
4. Создать или выбрать общий каталог результатов.
5. Запустить отдельный процесс SZFD для каждого видео.
6. Проверить код возврата процесса.
7. Найти CSV и каталог `clips` по правилам ниже.
8. Читать границы из CSV, не извлекать их из текста консоли.
9. Считать пустой CSV без строк событий корректным результатом «фраги не найдены».

Не запускайте два процесса для одного входного файла и одного выходного каталога
одновременно: они будут записывать одинаковые пути.

## Рекомендуемая команда

```powershell
& ".\SZFD-CLI.exe" `
  --input "D:\Video\match.mp4" `
  --output "D:\Video\montage" `
  --frame-step 30 `
  --multikill `
  --cut-before 10 `
  --cut-after 10 `
  --multifrag-gap 10 `
  --cut-mode copy `
  --quiet
```

`--multikill` автоматически включает нарезку. `--cut-mode copy` сохраняет потоки
без пережатия и работает быстрее, но начало клипа может сдвинуться к ближайшему
ключевому кадру. Для точных границ используйте `--cut-mode exact`; этот режим
перекодирует видео.

## Контракт результатов

При `--cut` или `--multikill` и входном файле `match.mp4`:

```text
<output>\match_frags\
├── match_fragtime.csv
├── clips\
│   ├── moment_001_00-03-58.mp4
│   └── moment_002_00-08-21.mp4
└── debug\                         только с --debug
```

Если `--output` не передан, папка `match_frags` создаётся рядом с исходным видео.
Без нарезки CSV записывается непосредственно в `<output>` или рядом с видео.

CSV имеет кодировку UTF-8 с BOM и следующие поля:

| Поле | Значение |
| --- | --- |
| `event` | Порядковый номер эпизода плашки |
| `seconds` | Начало события в секундах |
| `timecode` | Начало события в формате таймкода |
| `score` | Лучшее значение совпадения шаблона |
| `hits` | Число подтверждающих срабатываний |
| `last_seconds` | Последнее наблюдение плашки |
| `clip_group` | Номер итогового момента/клипа |
| `group_size` | Число эпизодов плашки в группе, не точное число убийств |
| `clip_start` | Начало монтажного диапазона в секундах |
| `clip_end` | Конец монтажного диапазона в секундах |
| `visible_seconds` | Наблюдаемая длительность эпизода |

Для монтажа используйте `clip_group`, `clip_start` и `clip_end`. Несколько строк с
одинаковым `clip_group` относятся к одному итоговому клипу.

## Коды возврата

| Код | Значение | Действие агента |
| --- | --- | --- |
| `0` | Видео успешно обработано | Проверить CSV и продолжить пайплайн |
| `1` | Ошибка входа, настроек, чтения видео или FFmpeg | Сохранить stderr и остановить этот файл |
| `2` | Проверочное изображение обработано, плашка не найдена | Не считать ошибкой видео-пайплайна |

Для видео отсутствие событий возвращает код `0`. Агент не должен определять успех
по числу найденных моментов или по локализованному тексту stdout.

## Выбор режима

- Нужны готовые клипы целых серий: `--multikill`.
- Нужны только таймкоды для собственного редактора: не передавать `--cut` и
  `--multikill`, читать CSV.
- Нужна максимальная скорость без пережатия: `--cut-mode copy`.
- Нужны точные монтажные границы: `--cut-mode exact`.
- Нужна диагностика ложных срабатываний: `--debug`.
- Короткая плашка пропускается: уменьшить `--frame-step` или `--min-hits 1`.
- Много ложных срабатываний: повысить `--threshold`, например до `0.78`.

Повторный поиск перед экраном смерти включён по умолчанию. Он отступает назад на
`--death-rescan 3` секунды и проверяет кадры с шагом `--death-frame-step 1`.

## Пакетная обработка

Агент должен фильтровать файлы до запуска SZFD, например по расширению, дате или
проекту. SZFD обрабатывает один входной файл за вызов. Для каждого видео используйте
один общий `--output`: уникальная папка `<имя_видео>_frags` предотвращает смешивание
результатов разных записей.

Пример псевдокода:

```text
for video in selected_videos:
    fps = read_video_fps(video)
    step = max(1, round(fps / 2))
    result = run(SZFD-CLI.exe, video, output, step, multikill, quiet)
    if result.exit_code != 0:
        report_failure(video, result.stderr)
        continue
    csv = output / (video.stem + "_frags") / (video.stem + "_fragtime.csv")
    moments = group_csv_rows(csv, key="clip_group")
    pass_to_editor(video, moments)
```

При интеграции непосредственно в Python используйте публичные функции `analyze`,
`export` и `process`, описанные в [README](README.md#python-api). Это надёжнее запуска
подпроцесса, если агент и SZFD работают внутри одного Python-приложения.
